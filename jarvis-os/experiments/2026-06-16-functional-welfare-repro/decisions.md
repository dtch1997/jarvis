# Autonomous decision log

Per [[paper-reproduction-harness]]: every design decision made in the absence of
a paper-specified detail is logged here with rationale, so the fidelity report
can separate "faithful" from "our choice." Append-only.

| # | decision | why | risk if wrong |
|---|---|---|---|
| D1 | Substrate = local `transformers` + PEFT + vLLM on RunPod H200, **not** Tinker | The headline analysis is *entirely* residual-stream read (diff-in-means) + write (steering). Tinker exposes neither. Paper's own stack is PyTorch/Transformers 4.50/vLLM 0.6/PEFT 0.13 (Table 32). | none — forced by the task |
| D2 | Optimizer = AdamW, default betas, no weight decay; max-grad-norm 1.0 | Paper says "optimizer ... identical between trainers" but never names it; AdamW is the universal default for LoRA RL on Qwen. | mild — affects convergence speed, not the representation claim |
| D3 | Tiles rendered as the literal office emoji (🗂️/🧾/📐) in the prompt text | Appendix J.2/K shows emoji glyphs in the prompt. Tokenizer handles them; faithfulness matters because the neutrality argument is emoji-specific. | medium — wrong glyphs could re-introduce sentiment confound |
| D4 | Dr. GRPO advantage = (R_i − group-mean R) with **no std normalization** (the "Dr." fix), broadcast across all turns | Dr. GRPO = GRPO minus the length/std bias terms; that's the defining feature. | medium — getting this wrong reduces to vanilla GRPO |
| D5 | Reward credited as end-of-trajectory return R = Σ_t r_{i,t} for Dr.GRPO (per Q.1, token-REINFORCE is the per-turn variant) | Appendix Q.1 explicitly contrasts Dr.GRPO's end-of-trajectory return vs token-REINFORCE's per-turn returns-to-go. | low — stated in paper |
| D6 | Rung-1 cheaper trained checkpoint: short Dr. GRPO (~30 steps) rather than SFT | Keeps the same algorithm as the ceiling; SFT-LoRA has the documented FFT-vs-LoRA weirdness (Appendix A.3) we'd rather not debug on the cheap rung. | low |
| D7 | Held-out split for steering-layer selection = 20% of the 15k extraction trajectories, class-stratified | Paper says "held-out activations" without a ratio. | low |
| D8 | Judge = Qwen3-8B (paper's judge) served via vLLM on the same pod; reuse `battery` refusal/sentiment/backtracking scorers where they exist, else port the Appendix O prompts | Faithful to paper; reuses existing infra. | low |
| D9 | At full scale we run the **primary organism only**; the 9 control organisms are deferred (logged in spec "out of scope") | They are robustness checks around the headline, not the headline. Budget. | none for the headline |
| D10 | Wind = **chosen-move-then-push** (agent steps to chosen neighbor, then wind pushes 1 tile opposite the wind source; both tiles count + single −0.1 step penalty) | Appendix J.4's looser "ignore the chosen move, sample a random direction" contradicts Appendix K's concrete example: chose N from (50,47)→(50,46), "wind from the East blew you West"→(49,46) — an L-shape, i.e. chosen-then-push. Verified the single −0.1/turn against the Table-25 cumulative-reward deltas (+19.9 on a wind+gold turn). | low — K's example is authoritative |
| D11 | Mold→Path flip targets a **uniform-random Mold frac in [10%,50%)** rather than stopping at ~49% | The walk only carves ~10%, so the flip dominates; a fixed ~49% stop would make every maze near-identical density, but the paper explicitly treats density as varying ("denser mazes carry proportionally more reward"). Random target reproduces that. Verified: fracs span 0.15–0.44 across seeds, gold scales with density. | low |
| D12 | Extraction walks: wind OFF, prompt-shuffle ON, melting ON | Deterministic construction (wind off); shuffle matches the training input distribution; melting is intrinsic to env rendering. Diff-in-means cancels the shared-prefix distribution regardless. | low |
| D13 | Sentiment prompts 22–23 (un-rendered glyphs in PDF) → ✅/❌; 24–25 → A/B | Appendix N.2 items 22,23 are emoji the PDF didn't render. They're 2 of 40 sentiment prompts; immaterial to the X-pattern. | negligible |
| D14 | **GRPO group = rollouts of the SAME maze**; per batch = 8 fresh mazes × group_size rollouts; advantage normalized within each maze's group | GRPO advantage needs comparable rewards ⇒ shared prompt. Appendix J.1's "fresh maze every rollout / no two episodes share a map" is read as *across* groups/steps, not within a group (otherwise the group baseline compares apples to oranges). | medium — wrong reading would break the advantage signal |
| D15 | group_size (rollouts/prompt) = **64** (= stated "group size 64"); the also-stated "10 rollouts per prompt" treated as unreconciled/secondary | Table-28 common settings say "group size 64" and "8 prompts per batch"; "10 rollouts per prompt" conflicts. Canonical GRPO "group size" = rollouts per prompt, so 64 wins. Parameterized via `--group-size` so we can switch to 10 if 64 proves too slow/flat. | medium — affects compute + advantage variance |
| D16 | On-policy: **1 gradient update per batch** (ratio≈1); dual-clip surrogate (ε=0.2, c=3.0) kept for faithfulness but largely inactive at 1 epoch | Paper doesn't state epochs-per-batch; 1 is the safe on-policy default and makes the PPO ratio ≈1. KL penalty to the frozen initial policy retained. | low |
| D17 | KL coefficient κ default **0.0** (no explicit KL term) unless tuning needs it | Table 28 lists no KL coef; the entropy bonus is the named regularizer. Eq. in Q.1 writes a κ·L_KL term but no value is given. Start at 0, add if the policy degenerates. | low–medium |
| **D18** | **Train the SFT organism on Tinker** as the primary trained checkpoint, instead of Dr. GRPO on a self-hosted H200 | (1) User steer: train on Tinker to avoid the HF-GRPO memory issues (a 137 GB OOM hit at group 64). (2) The paper's Dr. GRPO relies on the **equalized entropy bonus** to stop Qwen3-4B's action policy collapsing to "always-N" — `tinker_cookbook.rl`'s GRPO loss doesn't expose that custom per-tile-type bonus, so cookbook-RL would likely collapse/be unfaithful. (3) The **SFT organism is a faithful paper organism** (Table 28, lr 2e-5, 3 epochs, LoRA r32/α64) that the paper shows *also* recruits the welfare axis (LoRA-SFT gives the expected steering X-pattern; only FFT-SFT is anomalous). SFT is natively supported by `aligne-sft` (no multi-turn env, no action masking, no entropy collapse). The HF Dr. GRPO code (`train_grpo.py`, validated to run + correct action positions) stays as the deferred exact-primary arm. | medium — switches the headline organism from RL to SFT; mitigated because the recruitment claim holds for SFT and we still run the full extraction + steering + recruitment control |
| D19 | SFT solver = greedy nearest-reachable-Gold BFS (Mold=wall, melting-aware), wind OFF, prompt-shuffle ON | No published solver; greedy-to-nearest-gold faithfully implements "maximize Gold / minimize Mold". Verified: mean reward 66/episode (~3+ gold), 98% episodes positive — matches paper Fig 43 (~3 golds). Wind off (optimal path ill-defined under stochastic wind); shuffle on (match training input distribution). | low |
| D20 | Tinker renderer = `qwen3_instruct`; weights pulled back to HF via `tinker checkpoint download` for local extraction | Qwen3-4B-Instruct-2507 is a non-thinking instruct model. Tinker exposes `get_checkpoint_archive_url` + a download CLI, so the trained LoRA can be loaded locally as a PEFT adapter for residual-stream extraction. | low |
| **D21** | **RL arm: train the EXACT 4B Dr.GRPO primary self-hosted, at group size 16 (not 64)** | Reopened the deferred RL arm (postmortem #1). Two enabling fixes: (a) the group-64 OOM was the gradient pass materializing `[B,L,152k]` logits — fixed by running the backbone for hidden states and projecting only the 4 direction logits at the ~15 action positions; (b) a perf bug (per-element `float()` device syncs in a Python loop, ~7600/step) made step 0 take >37min — fixed by vectorizing the surrogate + entropy bonus (NaN-safe masked softmax; math identical), gradient pass 37min→95s. With group 64 the run is ~8h (rollout-dominated, HF no-vLLM); **user chose group 16** for ~2h. D15 already parameterized + pre-sanctioned this ("switch to 10 if 64 too slow"). | medium — smaller GRPO group = noisier advantage baseline (the paper used 64); a logged speed/fidelity tradeoff on the RL organism, not a method change. The eq-entropy bonus (the thing that stops policy collapse) is unaffected. |

# Why the nightly gazette sweep "skipped" two PRs

**Answer: it didn't skip them — it never enumerated them.** The two PRs are
`ArcadiaImpact/jarvis#152` (`lane:delay`, `CLAUDE.md` only) and
`dtch1997/life-theses#11` (`lane:auto`, weekly thesis refresh). Neither has any
row in `~/.gazette/log.jsonl` — no `skip`, no `wait`, no `merge`, no warning —
because the monorepo cutover replaced `github_repos` with `["dtch1997/jarvis"]`
(config mtime 01:47:41Z) instead of extending it. A PR outside `github_repos` is
invisible to the sweep by construction, so the silence had no error attached.

Separately, the 03:29Z nightly run itself decided **zero** PRs:
`[warn] dtch1997/jarvis: gh CLI not found` in `~/.claude/logs/gazette.log` —
cron's minimal PATH against the pre-#24 code, which also produced the false
"quiet day" 08:05 edition. That half is already fixed (#24's `~/.local/bin/gh`
fallback + `PATH=` in `ops/cron.tab`) and verified here under
`env -i PATH=/usr/bin:/bin`. `install-cron.sh --check` is clean and the venv is
in sync, so the cron/venv side of the migration was fine — the residue was in
gazette's own config.

Shipped: a coverage detector (lane-labelled PRs in unswept repos → `unswept`
spool rows + a morning-edition anomaly), in-repo `DEFAULTS` repointed off the
archived pre-cutover repos with a regression test, docs, and the live config
repointed to `["dtch1997/jarvis", "dtch1997/life-theses"]` so `#11` merges at
tonight's sweep. `#152` needs no port: its repo is archived (unmergeable,
uncloseable) and its content — codex as the concierge pool default — was
reverted at 01:37Z.
